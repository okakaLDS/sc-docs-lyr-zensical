# 排他マトリクス（使い方）

## 1. 使い方

このファイルは新しい排他マトリクスページを追加する際の**空のひな形**（実データを含まない）。
調査の結果、対象システムに排他制御機構が実在しないと判明した場合の記載例は、本ページ
「2. 調査結果（対象システム・実ソース）」を参照する。マトリクスの記入例（架空データ）は
[\[Sample\]5-4_排他マトリクス](<[Sample]5-4_排他マトリクス.md>)。

**追加手順**

1. まず、対象システムのソースコード全体を対象に、次の3パターンで排他制御の実装有無を網羅的に
   調査する：悲観ロック（`SELECT ... FOR UPDATE`等）、排他制御用の状態フラグ・管理テーブル、
   楽観ロック（更新日時比較等）。
2. 排他制御機構が実在する場合のみ、下記「排他マトリクス（機能単位）」「排他マトリクス（画面単位）」
   の様式に実データを記入する。行・列とも同じ機能一覧（または画面一覧）を同じ順序で並べ、交点に
   「凡例」の記号を記入する。
3. 調査の結果、排他制御機構が実在しない、または一部の画面にのみ限定的に存在する場合は、マトリクス
   を捏造せず、本ページ「2. 調査結果」のように、調査した対象範囲・
   調査したパターン・結論を正直に記載する（該当機能が0件だからといって空欄だらけのマトリクス表を
   作らない）。
4. 「凡例」の記号・条件文言はプロジェクトごとに異なるため、実際のプロジェクトの取り決めに合わせて
   修正する。

## 共通の記入ルール

「ほか」「等」での省略禁止／1件＝1行／グループ化した行でもキー列を空欄にしない、の3点は [記述ルール 節10「列挙と行の書き方」](<../5-9_標準設計書/5-9-1_記述ルール/[Sample]5-9-1_記述ルール.md#10-列挙と行の書き方一覧表の共通ルール>) を正とする（各ページに重複記載しない）。

## 2. 調査結果（対象システム・実ソース）

（記入：調査対象範囲（ソースディレクトリー・画面数）、調査した3パターン（悲観ロック／排他制御用
フラグ・管理テーブル／楽観ロック）それぞれの調査結果、結論を記載する。排他制御機構が一部の画面にの
み限定的に存在する場合は、対象画面名・実装内容（定数名・比較ロジック）を具体的に記載する。排他制御
機構が全く存在しない場合は、その旨と根拠を正直に記載し、機能単位／画面単位のマトリクスを作成しない
理由を明記する。）

## 3. 排他マトリクス（機能単位）

実行中の機能（主）、列＝それと同時実行できるか判定される機能（参照）。列見出しは機能名を省略せず、

## 5. 凡例

*記号の種類・条件文言はプロジェクトごとに異なる。以下はKCCS本サンプルで確認された凡例の例であり、
実際のプロジェクトの取り決めに合わせて修正すること。*

| 記号     | 意味                                 |
| -------- | ------------------------------------ |
| （空白） | 同時実行可能                         |
| ×        | 同時実行不可                         |
| 1        | 実行事業所が同じ場合、同時実行不可   |
| 2        | 実行部門が同じ場合、同時実行不可     |
| 3        | 実行ユーザーが同じ場合、同時実行不可 |
