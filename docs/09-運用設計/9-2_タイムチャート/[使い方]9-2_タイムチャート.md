# タイムチャート — 使い方

*記入用の様式は [空テンプレート](<[Template]9-2_タイムチャート.md>)、記入例は [サンプル](<[Sample]9-2_タイムチャート.md>) を参照。*

## 1. 参考様式

*全注（全注文システム）基本設計書 `Ⅷ-2.ﾀｲﾑﾁｬｰﾄ.xlsx` の構成に合わせている。
原本は「時間帯の帯チャート＋※注記」の構成だが、※注記の中身は分単位の実行時刻表や時刻を決めた理由だった。
本サイトではそれらを注記に埋めず、節を分けて構造化する。*

## 2. 記載のルール

| No. | 項目 | ルール |
| --- | ---- | ------ |
| 1 | 正とビュー | 正確な時刻・回数・起動順は「2. 起動スケジュール一覧」を正とする。節1（日次俯瞰）は節2 から起こす**ビュー**で、節2 を直したら必ず追随させる。節3 の小節には節2 の No. を書いて対応を取る。同じ組み合わせを持つ表を増やさない（タスク→バッチは節2 と 3-1、バッチ→タスクは 3-2 の 1 か所ずつ）。節1 の帯ラベルは **No.＋短い名前＋起動回（①②…）** とし、No. と起動回は節2 の行・トリガー番号に一致させる（タスク名の全文は書かない） |
| 2 | 行の単位 | 節2 は**スケジューラに登録された起動単位（タスク）ごとに 1 行**。1 タスクが複数のバッチを順に起動する場合は「起動するバッチ（実行順）」列に `1. A`／`2. B` と実行順の番号を付け、`<br>` で 1 件 1 行に全件書く（1 件だけなら番号なし）。1 バッチが複数のタスクから起動される場合は、該当する各行に書く（行をまとめない） |
| 3 | INPUT | スケジューラのエクスポート（Windows タスクスケジューラ一覧等）を INPUT とし、**登録されている全タスク**を載せる。節2 の冒頭に取得日を書く。スケジューラ上のフォルダー・実行ファイルの場所・作業フォルダーは本書に転記しない（スケジューラ一覧を正とする） |
| 4 | 周期の値 | **日次／週次／月次／年次／随時／不明** のいずれか。曜日限定で毎週動くもの（例：月〜土）は「日次」とし実行日に曜日を列挙する。「週次」は特定の曜日にだけ動くもの。手動起動は「随時」、登録が見つからず契機が確認できないものは「不明」と書き、備考に確認先を残す |
| 5 | 実行日・時刻 | 曜日は「月〜土」「月・水・金」のように**列挙**し、「平日」「営業日」は使わない。月次は「毎月1日」。トリガーが複数あるときは ①②… の番号（起動回）を付け、`<br>` で 1 件 1 行に全件書く（どの回でも「起動するバッチ」を全件順に実行する。1 件だけなら番号なし）。繰り返し設定は「08:34 から 30m間隔で4h」のように**開始・間隔・期間**で書く（回数はスケジューラの仕様で揺れるため書かない） |
| 6 | 時刻の根拠 | 実行時刻には**根拠**（何に合わせた時刻か）を書く。スケジューラのコメント欄・概要欄に記載があれば出典を添えて転記し、無いものは「不明（要確認）」と書く（推測で埋めない。推定を書く場合は「推定」と明記） |
| 7 | バッチファイル名 | 「起動するバッチ」は**スケジューラが実際に起動するファイル名**（拡張子なし。`COMM_FTP_FVCC007`）で書く。共通エンジンに引数を渡す形（`WebApi_Service.wsf VDRAD003`）は引数まで書き、バッチ別一覧（3-2）では引数の ID を 6.3 の行と対応づける。ランチャー経由（`undisplay.vbs X.bat`）は実処理の `X` を書き、ランチャーは備考に記す |
| 8 | 6.3 との関係 | [6.3 バッチ一覧](<../../06-システム設計書（一覧、管理台帳）/6-3_バッチ一覧/[使い方]6-3_バッチ一覧.md>) はソースコードから分かる情報のみを持ち、**実行契機・周期は本書だけが持つ**（二重管理しない）。6.3 に行が無いバッチがタスクから起動されている場合は**削除せず「6.3 未掲載」と明記**して載せ、ソース一式に存在しないものはその旨を 3-2 の備考に書く。6.3 との突合（未掲載・表記差・未登録）は設計書には載せず社内記録で行う |
| 9 | リンク | 節2 の導入文から 6.3 バッチ一覧へリンクする。5.5 CRUD表（バッチ行）・各バッチ処理定義書へのリンクは**作成済みの設計書だけ**張り、未作成は「未作成」と書く（リンク切れを作らない）。同じバッチを起動するタスクの逆引きは節2 の「起動するバッチ」列を検索する（対応図・逆引き表は持たない） |
| 10 | 載せないもの | スケジューラに登録が無く手動でも動かないバッチ（6.3 で対象外）は載せない。共通バッチエンジン（`COMM_ftp` 等）は単独では載せず、引数付きで起動されるものだけ 7 の形で書く |
| 11 | 節内リンク | 分量が多くなるため、節2 の No. にアンカー（`<a id="task-1"></a>`）を置き、節3 から `[No.1](#task-1)` でリンクする。節2 の「起動するバッチ」はコードスパンのファイル名で書き、8.2 バッチ処理定義書が作成済みのものだけそのフォルダーへリンクする（No.9）。特記の ※ は節3 の小節へリンクする。節見出しにも `<a id="sec2"></a>` を置き、本文中の「節2」参照をリンクにする。節2 の「起動するバッチ」の各項目には `<a id="bat-{No}-{順}"></a>` を置き、他の文書から実行順の単位でリンクできるようにする |
| 13 | 運用ロジック | 「なぜ月初だけ順序が違うのか」「なぜ 1 日 5 回に分けるのか」等の背景は節3 に 1 件＝1 小節で書き、節2 の「特記」列に ※番号で対応づける |
| 14 | 節2 の分割 | 節2 は**系統（節1 の帯と同じ A〜E）ごとに表を分け**、見出しを 2-A〜 とする。No. は全体の通し番号（アンカー `task-n` はそのまま）。列は No.／起動タスク名／処理の目的／周期・実行日／実行時刻（トリガー）／起動するバッチ（実行順）／時刻の根拠／特記 の 8 列で、全表同じ。系統ファイル（ジョブ定義）があれば表の見出し直下からリンクする（SC様レビュー 2026-09-17：一覧の情報量は OK・見づらさを改善） |
| 15 | 処理の目的 | 「処理の目的」は**タスク単位の 1 文**で「どこから何を取り込み（取得し）、どのテーブルをどう更新するか」を書く。1 行で完結させ、「同上」「No.n と同じ」だけの記述はしない（行単位で読んでも意味が取れるようにする。生成 AI に読ませる前提）。テーブル名・プロシージャー名・ファイル名はコードスパン。出典はソース（bat／SQL／SP／Python）を正とし、6.3 バッチ一覧・スケジューラの説明欄・コメント欄で補う。ソースで確認できない部分は「（要確認）」を付ける。バッチ単位の処理内容は 8.2 に書き、ここでは繰り返さない（SC様レビュー 2026-09-17：タスク毎の処理内容・目的が欲しい） |
| 16 | 表内の複数項目 | 1 セルに複数の項目を書くときは**順序があるか並列かを表記で分ける**：並列＝改行（`<br>`）で 1 行 1 項目、順序＝`1. 2.`（節2 の起動するバッチと同じ）、同じ操作を受けるテーブルの列挙＝「・」。読点で繋げない。|
| 17 | 他文書への導線 | 節2 の「起動するバッチ」→ [8.2 バッチ処理定義書](<../../08-システム機能設計書/8-2_バッチ処理定義書/[使い方]バッチ処理定義書.md>)（作成済みフォルダーのみリンク。未作成は名称のみ）→ 8.2 の各ページから 5.5 CRUD表（処理IDの行アンカー）・7.1 DBレイアウト（テーブルID）・7.2 ファイルレイアウトと 6.5 ファイル一覧（ファイルID）・8.3 DB(SQL)処理定義書（呼び出し一覧の PKG）へ辿る。8.2 側の張り方（テーブルID → 7.1、ファイルID → 6.5／7.2、呼び出し一覧 → 8.3、処理概要 → 5.5 と 9.2）は 8.2 使い方に定める（ベンダーへ依頼中）。本書は 8.2 より先へ直接リンクしない（情報を本書に集約しない） |
