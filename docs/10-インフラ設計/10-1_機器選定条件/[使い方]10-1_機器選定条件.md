# 機器選定条件 — 使い方

*記入用の様式は [空テンプレート](<[Template]10-1_機器選定条件.md>)、記入例は [サンプル](<[Sample]10-1_機器選定条件.md>) を参照。*

## 1. 10章の前提（リバース案件での位置づけ）

> **📌 まず「調達方針」を確定させる**
>
> *本プロジェクトは既存システムのリバースであり、新インフラの位置づけは案件の方針で大きく変わる。
> **まず調達方針を確定させること**。現行機を流用するなら本章の大部分は「現行構成に準拠」で足りる。
> なお全注の設計書にはインフラ章に相当する参照元が無いため、本章の様式は本サイト独自の構成。*

## 2. 各節に書くこと

| 節 | 書くこと |
| -- | -------- |
| 1. 調達方針 | 新インフラをどう調達するかの大方針（新規調達／更改／流用／クラウド移行）。ここが決まらないと以降が書けない。現行・将来の別は基本設計の版改訂で管理 |
| 2. 選定条件 | 性能・可用性・保守（EOL/EOS）・コストの条件と根拠。「流用」なら「現行構成に準拠」でよい |
| 3. 前提とする負荷条件 | 同時接続・トランザクション・データ増加量など。レスポンスは [レスポンス一覧](<../../06-システム設計書（一覧、管理台帳）/6-9_レスポンス一覧/[Template]6-9_レスポンス一覧.md>)、データ量は [開発方針](<../../02-システム化の要件・基本方針/2-2_開発方針/[Template]2-2_開発方針.md>) と整合させる |
| 4. 導入の経緯・インフラ構成の変遷 | 基盤・製品を選んだ経緯（選定主体・条件・採用理由・前史）と、導入後の構成の変遷を時系列の表で残す。流用案件では「なぜ今の構成なのか」の根拠になる |
