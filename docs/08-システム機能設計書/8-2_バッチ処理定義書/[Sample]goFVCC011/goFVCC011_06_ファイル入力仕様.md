## 3. 取込方式

| 項目                   | 内容                                                                                   |
| ---------------------- | -------------------------------------------------------------------------------------- |
| 取込ツール             | Oracle SQL\*Loader（`sqlldr`）                                                         |
| 制御ファイル           | `FVCC011loading.ctl`                                                                   |
| ロードオプション       | `ROWS=1000`／`DIRECT=TRUE`／`SKIP=2`（`.ctl`のOPTIONS）、`readsize=1000000`／`rows=128`（コマンドライン引数、`goFVCC011.bat`より） |
| 登録方式               | `APPEND`（既存データを残したまま追記）                                                 |
| 取込対象の絞り込み条件 | 明細：`WHEN (RECORD_KBN <> '99')`／トレーラ：`WHEN (DATA_KBN = '99')`。`TRAILING NULLCOLS`により末尾欠落項目はNULL扱い |
| エラーレコード出力先   | `.\UPLOAD_DAT\FVCC011.bad`（BADFILE）                                                   |
| 取込先テーブル         | `FVCC011`（明細）／`SQLLDR_UPDATE_TMP`（トレーラ）                                     |

**特記事項**

1つの連携ファイルに**2種類のレコード**が混在し、`WHEN`句によって**異なる2テーブルへ振り分けて**ロードされる。
このため入力項目は下記の通りレコード種別ごとに定義する。論理名（日本語項目名）は`DBレイアウト定義書`
（Excel、本サンプル作成時点で未参照）との突き合わせが必要なため、本サンプルでは物理名／データ型の列のみとし、
論理名列は設けない。

## 5. 取込制御

| 項目                     | 内容                                                                                       |
| ------------------------ | -------------------------------------------------------------------------------------------- |
| ファイル未存在時の扱い   | `goFVCC011.bat`の`IF EXIST`ガードによりロード処理一式をスキップする。ログには開始・終了時刻のみ出力される（エラーとしない） |
| データ0件時の扱い        | ソース上、0件を判定する処理は無い。`CB46`への差分INSERTが0件挿入となるのみ                 |
| 不正レコード検出時の扱い | SQL\*Loaderが`.\UPLOAD_DAT\FVCC011.bad`へ出力し、残りのレコードのロードを継続する。BADFILEの件数チェック・通知処理は無い |
| 重複レコード検出時の扱い | `APPEND`のため制御なし。同一世代の二重取込は呼出元`COMM_ftp.bat`の世代比較で防止する       |
| 取込後のファイル処理     | 退避・リネーム・削除のいずれも行わない                                                     |
