### 更新概要

本機能は「検索条件保存」ボタンを持たず、**検索・ダウンロードの実行時に検索条件を自動保存する**
（ユーザーが明示的に保存操作を行わない点がS021Gの`LYR03_DEF_TBL`更新と異なる）。

| 操作No. | 種別   | 契機（トリガー）           | 概要                                                                                                   |
| ------- | ------ | -------------------------- | ------------------------------------------------------------------------------------------------------ |
| INSERT  | INSERT | 「注残検索」ボタン押下時／「ダウンロード」ボタン押下時 | 当該ユーザー・`DEFAULT_NO='JZ1'`の行が存在しない場合、画面の検索条件を新規登録する。 |
| UPDATE  | UPDATE | 「注残検索」ボタン押下時／「ダウンロード」ボタン押下時 | 当該ユーザー・`DEFAULT_NO='JZ1'`の行が存在する場合、画面の検索条件で上書きする。     |

### 更新条件

```text
■存在判定（INSERT／UPDATEの振り分け）
SELECT COUNT(LYR03_DEF_TBL.USER_CD)
  FROM LYR03_DEF_TBL
 WHERE LYR03_DEF_TBL.USER_CD    = Z.ユーザーID AND
       LYR03_DEF_TBL.DEFAULT_NO = 'JZ1'
　→ 0件ならINSERT、1件以上ならUPDATE

■INSERT-条件
条件なし（上記存在判定で0件の場合に実行）。

■UPDATE-条件
LYR03_DEF_TBL.USER_CD    = Z.ユーザーID AND
LYR03_DEF_TBL.DEFAULT_NO = 'JZ1'
```

**`DEFAULT_NO`について**：本画面は`struct.setDEFAULT_NO("JZ1")`により**固定値`'JZ1'`**を使用する。
S021Gのように複数セット（`U31`〜`U36`）を切り替える機構は持たないため、1ユーザーあたり1行のみ保存される。

### 特記事項

- **画面に対応する入力項目を持たないカラム**（No.5／No.12／No.20〜22）：`LYR03_DEF_TBL`は
  複数画面で共用されるテーブルであり、SQLは全カラムを対象にしている。JZ01の検索条件欄には
  これらに対応する入力項目が存在しないため、常に`null`（または初期値）が保存される。
  なお`lyr07_JZ01.jsp`のデッドコード`Search_Rule()`はこれらの項目をフォーム要素として参照しており
  （[チェック処理概要](JZ01_02_チェック処理概要.md)「特記事項（デッドコード）」参照）、
  他画面から流用した際にSQL側だけが引き継がれたことが推測される。
- **監査列**：INSERT／UPDATE文には`CREATED_*`／`UPDATED_*`列が現れない。`DataObject`基底クラスに
  `m_sCreateProgramName = "lyr07_JZ01"`／`m_sUpdateProgramName = "lyr07_JZ01"`が設定されており、
  監査列はフレームワーク側で自動付与される（詳細は共通機能設計書の該当節を参照）。
- **同一テーブルを更新する他機能**：`LYR03_DEF_TBL`はS021G（`U31`）も更新する
  （[\[Sample\]S021G_売上予定管理](<../[Sample]S021G_売上予定管理/U31_05_更新条件表/LYR03_DEF_TBL_検索条件保存_02.md>)参照）。
  `DEFAULT_NO`で画面ごとに行を分けているため競合しない。
