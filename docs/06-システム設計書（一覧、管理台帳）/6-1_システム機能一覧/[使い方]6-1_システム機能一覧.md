## 1. 機能一覧

システムが提供する機能を一覧化した管理台帳である。1機能＝1行で、
**画面・帳票の機能を対象**とする。**バッチは機能に含めない**
（[バッチ一覧](<../6-3_バッチ一覧/[Template]6-3_バッチ一覧.md>)（6.3）で`バッチID`を主キーに独立管理する。
理由は下記「バッチを機能に含めない理由」を参照）。

画面・帳票の明細は[画面・帳票一覧](<../6-2_画面・帳票一覧/[Template]6-2_画面・帳票一覧.md>)（6.2）に分離しており、
`機能ID`で連結する。

**機能の一覧と部門・機能分類を1表に統合**し、**部門（大分類）→機能分類（中分類）→機能ID（小分類）**の順に並べる。
部門・機能分類は08系詳細設計書（機能ごとにDB処理定義書・バッチ処理定義書・画面設計書をグルーピングする構成）を組む際の分類根拠であり、AZR-418で有識者から得た方針をそのまま反映している。
呼出元（どの画面・バッチから呼ばれるか）は[画面・帳票一覧](<../6-2_画面・帳票一覧/[Template]6-2_画面・帳票一覧.md>)（6.2）・[バッチ一覧](<../6-3_バッチ一覧/[Template]6-3_バッチ一覧.md>)（6.3）で管理し、本表では持ちません（二重管理を避けるため）。

*本表は「機能とは何か」を定義する起点のドキュメント。他の6系ドキュメント（6.2・6.3・6.4）・
08系詳細設計書は、すべてこの機能IDを参照して連結する。*

**機能IDは自己採番ではなく、客先提供の機能一覧（`納期管理‗機能一覧.xlsx`の`機能分類`シート、
`OPF(Java)`列）またはソースコードのパッケージ名から取得する。**（4-1の`共通機能ID`＝`C0XX`のような
自己採番とは性質が異なる。詳細は下記「機能ID」の項目説明を参照）

**サンプル様式**

| No. | 部門 | 機能分類 | 機能ID | 機能名 | 備考 |
| --- | ---- | -------- | ------ | ------ | ---- |
| 1   | 営業 | 納期管理 | S0XX1  | 機能A-1 |  |
| 2   | 営業 | 納期管理 | S0XX2  | 機能A-2 |  |
| 3   | 営業 | 実績管理 | S0YY1  | 機能B-1 |  |
| 4   | 共通 | サブ     | M0XX   | 機能M-1 |  |
| 5   | 共通 | -        | M0YY   | 機能M-2 | 未使用 |

*各項目の意味と記入内容：*

- ***No.*** … 機能の通し番号（1から採番）。**部門→機能分類→機能ID**の順に並べたうえで通し番号を振る。
- ***部門*** / ***機能分類*** … 客先提供の機能一覧（`納期管理‗機能一覧.xlsx`の`機能分類`シート）の
  `部門`列・`分類`列の値をそのまま転記する（自己判断で分類し直さない）。同シートは`部門`
  （`営業`／`製造`／`共通`）→`分類`（`納期管理`／`出荷管理`／`実績管理`／`サブ`／`-`）の2階層で
  既に整理済みのため、機能ID（`OPF(Java)`列）をキーに突合するだけでよい。
  客先の機能一覧に登録が無いOPF（`JSP_import`シート等で存在は確認できるが`機能分類`シートに
  行が無いもの）のみ、AZR-418の方針に従いこちらで判定する：
    1. OPFが`Orteus標準`（フレームワーク部分）で、かつ2つ以上の画面／バッチから呼ばれている
       （[画面・帳票一覧](<../6-2_画面・帳票一覧/[Template]6-2_画面・帳票一覧.md>)（6.2）・[バッチ一覧](<../6-3_バッチ一覧/[Template]6-3_バッチ一覧.md>)（6.3）で確認） → `部門`・`機能分類`とも**共通**
    2. どこからも呼ばれていない → `部門`・`機能分類`とも**その他**
- ***機能ID*** … **自己採番しない。** 画面・帳票系は客先提供の機能一覧（`納期管理‗機能一覧.xlsx`の
  `機能分類`シート、`OPF(Java)`列。例：`S001A`）またはソースの`package`宣言（例：
  `jp.co.kyocera.in.kok.sc_g.S001A`の末尾`S001A`）から取得する`OPFコード`をそのまま使う。
  1機能が複数OPF（画面＋帳票の出力バリエーション等）にまたがる場合は、代表となる画面のOPFコードを機能IDとし、
  他のOPFは[画面・帳票一覧](<../6-2_画面・帳票一覧/[Template]6-2_画面・帳票一覧.md>)側の明細行に記載する。
  客先の機能一覧に登録が無いOPF（`JSP_import`シート等で存在は確認できるが`機能分類`シートに
  行が無いもの）は、`【要確認】`として客先へ確認する。
- ***機能名*** … 画面タイトル・帳票名称を要約した日本語名称。客先提供の機能一覧
  （`納期管理‗機能一覧.xlsx`の`機能分類`シート、`項目`列）の値をそのまま使う。
- ***備考*** … 補足事項があれば記入する（客先提供の機能一覧の`備考`列も参考にする）。特になければ空欄でよい。
  ソース調査の結果、その画面がどこからも呼ばれていない（呼出元が無い）と判明した場合は`対象外（未使用）`と
  記載する（旧`未使用`から表記統一。バッチの対象外判定は[バッチ一覧](<../6-3_バッチ一覧/[Template]6-3_バッチ一覧.md>)（6.3）・
  `batch-processing-spec/[使い方]バッチ処理定義書.md`0-6節参照）。
  呼出元の有無は[画面・帳票一覧](<../6-2_画面・帳票一覧/[Template]6-2_画面・帳票一覧.md>)（6.2）で突合して判断する。調査だけでは判定が難しい場合は、
  空欄のままにし、基本設計時に客先へ未使用機能をヒアリングする（AZR-417にて客先指摘）。
- ***バッチを機能に含めない理由*** … 機能（画面・帳票）は客先提供の機能一覧・ソースの
  `package`宣言という自然な識別子（OPFコード）を持つが、バッチにはその対応が無く、
  1バッチが複数機能から呼ばれる／1機能から複数バッチが呼ばれるなど機能と1対1に対応しない
  ケースがあるため、[バッチ一覧](<../6-3_バッチ一覧/[Template]6-3_バッチ一覧.md>)（6.3）で独立管理する。
