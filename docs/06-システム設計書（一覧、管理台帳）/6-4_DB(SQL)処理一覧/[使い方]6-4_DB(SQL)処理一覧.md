## 概要

システムが持つDB処理（PACKAGE／PROCEDURE／FUNCTION等のDBオブジェクト）を
1オブジェクト＝1行で一覧化した管理台帳である。

**DB処理は他の一覧（6.1・6.2・6.3）と違い、`機能ID`によるグループ化を行わない。**
理由：DB処理（PACKAGE等）は複数の機能から共用されることが多く、特定の1機能に
帰属させると重複や漏れが生まれるため（AZR-418にて客先指摘）。

**呼び出し元は「1. DB(SQL)処理一覧」本表とは別に「2. 呼び出し元一覧」で管理する。**
1つのDB処理を複数の呼び出し元（画面・バッチ）が使うことが多く、本表の1セルに
種類の異なる呼び出し元（画面IDとバッチID等）をまとめて記載すると読みづらくなるため、
呼び出し元1件＝1行の別表に切り出す。

## 1. DB(SQL)処理一覧

**サンプル様式**

| No. | スキーマ | オブジェクト名 | 種別 | 処理概要 | 備考 |
| --- | -------- | -------------- | ---- | -------------------------------------------- | ---- |
| 1   | SCHEMA_A | PKG_A          | PACKAGE | PKG_Aの処理概要を1文で。 | |

*各項目の意味と記入内容：*

- ***No.*** … DB処理の通し番号。機能単位のグループ化は行わないため「No.」列は1つのみ。
  「2. 呼び出し元一覧」の`DB処理No.`列から本表の行を参照する。
- ***スキーマ*** … オブジェクトの所有スキーマ（例：`LYR19`／`SCSALES`）。テーブル名とは
  列を分けて管理する（AZR-418にて客先指摘：スキーマ名とテーブル名は列を分ける。この方針は
  08系DB処理定義書の更新条件表にも適用する）。
- ***オブジェクト名*** … PACKAGE／PROCEDURE／FUNCTION等の実オブジェクト名（例：`NOUKI_PKG`）。
  ソースの`CREATE PACKAGE`等の宣言、またはJavaからの呼び出し文字列（`{call PKG.PROC(...)}`等）
  から取得する。
- ***種別*** … `PACKAGE`／`PACKAGE BODY`／`PROCEDURE`／`FUNCTION`／`TRIGGER`／`TYPE`のいずれかを
  記入する。
- ***処理概要*** … 1文でそのDB処理が何をするかを説明する。
- ***備考*** … 補足事項があれば記入する。特になければ空欄でよい。
  「2. 呼び出し元一覧」で当該DB処理の行が1件も無い（＝静的な呼び出しが`未検出`）だけでは、
  直ちに`未使用`と記載しない（動的SQL・外部起動の可能性があるため。「2. 呼び出し元一覧」の
  項目説明を参照）。ソースコード調査により本当にどこからも呼ばれていないと判断できた場合のみ
  `未使用`と記載する。調査だけでは判定が難しい場合は空欄のままにし、基本設計時に客先へ
  未使用機能をヒアリングする（AZR-417にて客先指摘）。

## 2. 呼び出し元一覧

DB処理を呼び出す画面・バッチを、呼び出し元1件＝1行で一覧化する表。
1つのDB処理を複数の呼び出し元が使う場合は、`DB処理No.`／`スキーマ`／`オブジェクト名`が
同じ行を呼び出し元の数だけ並べる。

**サンプル様式**

| DB処理No. | スキーマ | オブジェクト名 | 呼び出し元区分 | 呼び出し元 |
| --------- | -------- | -------------- | -------------- | ---------- |
| 1         | SCHEMA_A | PKG_A          | 画面           | S0XX1      |
| 1         | SCHEMA_A | PKG_A          | バッチ         | BATCH_NAME |

*各項目の意味と記入内容：*

- ***DB処理No.*** … 「1. DB(SQL)処理一覧」の`No.`列と一致させる（外部キー）。
- ***スキーマ***／***オブジェクト名*** … 「1. DB(SQL)処理一覧」の該当行と同じ値を転記する
  （表を分けて参照する手間を減らすため、あえて重複記載する）。
- ***呼び出し元区分*** … `画面`／`バッチ`／`DB内`のいずれかを、1行につき1つ記入する。
  `DB内`は**他の DB(SQL) 処理（PACKAGE／PROCEDURE／FUNCTION／TRIGGER／TYPE）から呼ばれる**場合
  （PACKAGE の中で自分自身のサブプログラムを呼ぶものは書かない）。
  バッチ → DB 処理の 1 段目は`バッチ`行で、DB 処理から先の連鎖（例：`FVCF006after_load.sql` → `FVCF006_PKG` →
  `VDRAD003_004_PKG` → `SP_JCHZN_TBL_PK`）は`DB内`行を順に引いて辿る。8.2 バッチ処理定義書の「呼び出し一覧」は
  1 段目しか持たないため、2 段目以降の呼び出し関係の正は本表である。
  「1. DB(SQL)処理一覧」側に対応する行が無い（＝本表に1行も現れない）DB処理は、
  静的な呼び出しが見つからなかった（`未検出`）ことを意味する。動的SQL・外部起動の
  可能性があるため「未使用」とは断定しない。
- ***呼び出し元*** … 呼び出し元の機能ID／バッチIDを、1行につき1件のみ記入する。`DB内`の場合は呼び出し元の
  オブジェクト名を書き、PACKAGE からの呼び出しは`PKG名.サブプログラム名`までを 1 件とする（同じ PKG の別サブプログラムから
  呼ばれていれば行を分ける）（機能ID・
  バッチIDの出所はそれぞれ[システム機能一覧](<../6-1_システム機能一覧/[Template]6-1_システム機能一覧.md>)（6.1）・
  [バッチ一覧](<../6-3_バッチ一覧/[Template]6-3_バッチ一覧.md>)（6.3）の「使い方」参照）。**「ほか」で省略したり、
  1セルに複数件をまとめて記載したりせず、呼び出し元1件＝1行に分けて全件を記載する**
  （AZR-418にて客先指摘：「ほか」はNG。全部記載するか、構造的に網羅不可なら項目ごと
  無くすかのどちらかにする）。
