# 共通機能処理概要 — 使い方

## 使い方

本ドキュメント（4.2 共通機能処理概要）は、用途別に3種類のファイルへ分けて管理する。

| ファイル | 位置づけ | 中身 |
| -------- | -------- | ---- |
| [\[Template\]{id}_{class-name}_{function-name}.md](<[Template]{ID}_{クラス名}_{機能名}.md>) | 記入用の空テンプレート | 実データを持たない、ほぼ空のひな形 |
| [\[Sample\]PartialSQLGenerator](<[Sample]AZRCM001_PartialSQLGenerator_動的検索条件SQL生成.md>)／[\[Sample\]DisplayMessageUtil](<[Sample]AZRCM002_DisplayMessageUtil_監査列自動付与.md>) | 実データ例 | SC納期管理（`lyr07-KCCS`）の実クラスを調査して記入した記入例 |
| **本ページ（\[使い方\]）** | 書き方の指南 | 各章に何をどう書くかの解説 |

**新しい共通機能ページを作る手順**

1. [4-1 共通機能一覧](<../4-1_共通機能一覧/[使い方]4-1_共通機能一覧.md>)の掲載基準（1処理単位、2機能（OPFパッケージ）以上から
   呼び出し）を満たすことをソースコードで確認する。1機能からしか呼ばれない処理は対象外。
2. [\[Template\]{id}_{class-name}_{function-name}.md](<[Template]{ID}_{クラス名}_{機能名}.md>)を複製し、
   ファイル名の`{class-name}`／`{function-name}`を実値に置き換える。`{id}`部分は`AZRCM001`のように
   `AZR`＋`CM`＋3桁連番（既存IDの次番）に置き換える（例：`AZRCM001_PartialSQLGenerator_動的検索条件SQL生成.md`）。
3. 本ページの各章の説明に従って内容を記入する。
4. [4-1 共通機能一覧](<../4-1_共通機能一覧/[Sample]4-1_共通機能一覧.md>)側にも同じIDで行を追加し、
   マトリクスと使用明細の両方を更新する（`[Template]`は実データを持たない空のひな形のまま保つため、
   実際の行を追加する先は`[Sample]`側）。

**共通の記入ルール**

- ***事実のみを書く*** … 記載内容は必ずソースコードで裏を取る。推測・コメントの雰囲気で書かない。
  調査していない事項は「未調査」と明示する（空欄のままにしない）。
- ***該当しない章は「該当なし」＋理由*** … 章そのものを削除しない。章立ては全ページで揃える。
- ***行番号は書かない*** … 呼び出し箇所の行番号は、ソース改修のたびに設計書の更新が必要になり
  管理の手間が増えるため記載しない（AZR-415にてKCCS様指摘）。呼び出し元は機能ID（OPFパッケージ）／
  ファイル単位までとする。
- ***他ドキュメントへのリンク・参照は、参照先が実データを持つ場合のみ書く*** … 参照先が
  `[Template]`接頭辞のファイル（＝実データを持たない空のひな形）である場合、そこへの
  「〜の調査結果によると」「〜のとおり」という参照は**事実の裏付けにならない**ため書かない。
  ソースコードから追えない事項を他ドキュメントへの参照で埋めることも同様に禁止する
  （情報が無いなら「未調査」または「該当なし」と書く。存在しない調査結果を作らない）。
- ***「ほか」「等」で列挙を打ち切らない*** … 一覧表（共通機能・呼び出し元・更新項目 等）を
  `ほか`／`等`／`など`／`その他`／`…`／`etc.`で省略しない（AZR-418にてKCCS様指摘：
  「例示でないのなら、全部記載するか、構造的に網羅不可なら項目ごと無くすか」）。
  認められる書き方は次の3つのみ。①**全件を列挙する** ②**構造的に列挙しきれない場合は理由を明記して
  その列・項目ごと設けない**（中途半端な一覧を残さない） ③**調査が終わっていない場合は
  `（記入：<未記入の理由>）`** と書く（作業が未完である印であり、完了を装う`ほか`とは意味が異なる）。
  唯一の例外は`記入例`／`例：`と明示している箇所。なお`全項目`は省略表記ではないため、そのまま残す。
- ***複数件をまとめて記載しない（1件＝1行に分ける）*** … 上記「ほか」「等」禁止ルールの一部として、
  対象が複数ある場合に1つの行・1つのセルへカンマ区切りや箇条書きでまとめて記載することも禁止する
  （AZR-418にてKCCS様指摘）。**対象ごとに行を分け、1件＝1行で全件を記載する。**
- ***グループ化した行でもキー列を空欄にしない*** … マークダウンの表で、1つの行に対して複数行が
  紐づくことを表すために空のセルを入れると検索性が下がるため、必ず値を入れる（AZR-413コメントにて
  KCCS様指摘）。Excelの縦方向セル結合に相当する見た目を再現するために先頭行以外を空欄にすることは
  禁止する。**グルーピングのキーとなる列は全ての行に同じ値を繰り返して記入する。**
- ***共通機能IDの採番規則*** … `AZR`（システムID）＋`CM`（Commonの略）＋3桁連番（例：`AZRCM001`、
  `AZRCM002`）。`ID_No_採番監査.md`にてKCCS様確認済み。詳細は
  [4-1 共通機能一覧](<../4-1_共通機能一覧/[使い方]4-1_共通機能一覧.md>)の「共通の記入ルール — 共通機能IDの採番規則」参照。

## 1. 共通機能

| 共通機能ID | 機能名       |
| ---------- | --------------- |
| （記入）   | （記入：機能名） |

*各項目の意味と記入内容（`【抽出】`／`【AI】`／`【要確認】`の凡例は「2. 処理概要」の
「記入元の凡例」を参照）：*

- ***共通機能ID*** … ソースコードからは取得できない（ソースコードに存在しない、ドキュメント作成側が
  付与する管理用の番号＝自己採番）。正式な採番方法は`ID_No_採番監査.md`にてKCCS様確認済み：
  `AZR`（システムID）＋`CM`（Commonの略）＋3桁連番（例：`AZRCM001`、`AZRCM002`）。既存IDと
  重複しないよう、次に追加する行は採番済みの最大値の次番を使う。
  [4-1 共通機能一覧](<../4-1_共通機能一覧/[Sample]4-1_共通機能一覧.md>)の「共通機能一覧（ロジック共通化）」表の
  IDと**必ず一致させる**。
- ***機能名*** … この共通機能を一言で表す名称。ソースにコメント／Javadoc等、名称の根拠となる
  記載があればそれを優先して転記する。**根拠が見つからない場合はAIが名称を創作しない** ——
  「（記入：命名根拠となるコメント等が見つからないため未確認）」と書く。一覧側の「機能名」列と
  同じ文字列にする。

*この表の直後に、対象の実クラス名（パッケージ込みフルパス）を書く。*

- ***クラス名*** … `【抽出】`ソースの`package`宣言＋`class`宣言から機械的に取得できる
  （例：`PartialSQLGenerator.java`の1行目`package jp.co...com.sql;`と6行目
  `public class PartialSQLGenerator`から`jp.co...com.sql.PartialSQLGenerator`が決まる）。
  推測の余地が無い、最も確実に自動生成できる項目の1つ。
- ***クラスの性格***（staticユーティリティ／インスタンスを保持する窓口クラス／内部で委譲する
  実装クラス 等）… `【抽出】`コンストラクタの有無、メソッドの`static`修飾子、フィールドの有無
  から機械的に判定できる。
- *1つの機能が複数クラスにまたがる場合は、その役割分担（どちらが窓口でどちらに処理を委譲するか）も
  `【抽出】`呼び出し関係（一方のクラスが他方のメソッドを呼んでいるか）から記述できる。*

## 2. 処理概要

*KCCSフォーマットのExcelサンプル`Ⅲ-2.共通機能処理概要.xlsx`（全14シート）の`【処理概要】`に対応する章。*

**様式は表ではなく文章（prose）**

*サンプルの`【処理概要】`は表ではない。導入文が数行あり、続いて`①②③`で処理を並べ、
その中を`・`で細分し、例外条件を`※`で注記する形である（`KAZS003`／`KAZS009`）。
表になっているのは`KAZS012`の「2) 対象項目について」のように、項目一覧を持つ場合だけ。
本テンプレートもこれに合わせ、本文は文章、対象項目のみ表とする。*

**1ページ＝1機能**

*サンプルでは同じクラス`AZSNumberingUtils`が`KAZS001`／`KAZS002`／`KAZS004`の3シートに分かれている。
つまり**1ページ＝1つの処理内容**であり、クラス単位ではない。同じクラスでも処理内容が異なれば
別IDを振って別ページを作る（[4-1 共通機能一覧](<../4-1_共通機能一覧/[使い方]4-1_共通機能一覧.md>)の「1行＝1処理」と1対1で対応）。*

### 記入元の凡例

*テンプレートの各`（記入：…）`には、その内容がどこから来るのかを示す記号を付けている。
自動生成ツールは`【抽出】`だけを機械的に埋め、`【AI】`は要約・推論して下書きし、
`【要確認】`は空欄のまま残して確認依頼に回す。*

| 記号 | 意味 | 生成後の扱い |
| ---- | ---- | ------------ |
| `【抽出】` | ソースコードから直接取得できる事実 | レビューは形式確認のみ |
| `【AI】` | AIが要約・推論して生成する | **必ず人がレビューする** |
| `【要確認】` | ソースからは判定できない | KCCS様・客先へ確認してから記入 |

*内容ごとの分類：*

| 記入内容 | 分類 | 補足 |
| -------- | ---- | ---- |
| クラス名・パッケージ・メソッド名・引数型・戻り型・static有無 | `【抽出】` | シグネチャをそのまま取得 |
| 送出する例外の型 | `【抽出】` | `throw`文から取得 |
| 定数・リテラル値、設定ファイルのキー名と既定値 | `【抽出】` | |
| SQL文字列・テーブル名・カラム名 | `【抽出】` | 文字列リテラルから取得 |
| 未実装スタブ（`return null;`のみ、`TODO`コメント） | `【抽出】` | 現状の実装事実として記載する |
| 呼び出し元パッケージ・ファイル・件数 | `【抽出】` | メソッドのcall siteで判定（`import`は根拠にしない） |
| 機能の概要（何のために存在するか） | `【AI】` | 意図はコードに書かれていない |
| 処理の流れ（`①②③`への分解） | `【AI】` | 制御フローを人が読む粒度へ要約 |
| 業務ルールの意味（式が業務上何を表すか） | `【AI】` | 例：編集回数カウンタの折り返し式の意味 |
| 呼び出し契機（「検索実行時」等） | `【AI】` | 呼び出し元メソッド名から推定 |
| 対象項目の`○`／`×`／`△`判定 | `【要確認】` | 業務判断。ソースには存在しない情報 |
| 呼び出し元の機能名（`S001A`＝`日程表`等） | `【要確認】` | `納期管理‗機能一覧.xlsx`の`機能分類`シートから補完 |
| `課題No.` | `【要確認】` | Backlogを見て人が付与 |

### 2. 冒頭（概要）

*本機能の概要を1〜3文。何のために存在し、呼び出し元がどのタイミングで何を得るのか。
サンプル`KAZS009`の「注文納期、製伝分納を入力する画面には「ソート」ボタンが設けられている。」のように、
まず前提の状況から書き始めるとよい。*

### 2.1 処理の流れ

*`①②③`で処理を順に並べる。分岐・例外送出・戻り値の決まり方まで含める。*

- ***導入文*** … 「並び替え処理は以下に従って行う。」のように、以下の列挙が何の手順かを示す1行。省略可。
- ***`①②③`*** … 1ステップ＝1つの`①`。1つの`①`が複数行になるのは構わない（サンプルも複数行）。
- ***`-`（細目）*** … `①`の中で条件を場合分けするときに字下げして書く
  （サンプル`KAZS009`の`③`が`・`で出荷指示情報の扱いを補足しているのと同じ形）。
- ***`※`（注記）*** … 「なぜそうなるのか」の補足や例外条件。サンプルでは
  「※ …フォーカスアウトした場合、自動で0が入力される仕様のため。」のように理由を書いている。
- *ステップ数が多く章立てが必要な規模になった場合は、サンプル`KAZS012`のように
  `1) 概要` `2) 対象項目について`と大きく分けてよい。*

### 2.2 対象クラス／メソッド

*`Ⅲ-1.共通機能一覧.xlsx`の「クラス」列（例：`AZSCommonUtils#sortNokiList(GListData, String[][])`）に対応。*

- *クラスは**パッケージ込みフルパス**で書く。*
- *メソッドは**引数型まで**書く（同名オーバーロードを区別するため）。*
- *1機能が複数クラスにまたがる場合は、クラスごとに入れ子で並べ、役割分担を用途欄に書く。*
- *クラスが特定されない機能も存在する（サンプル`KAZS007`／`KAZS008`／`KAZS011`は
  `ｸﾗｽ`列が空欄）。その場合は「該当なし」とする。*

### 2.3 業務ルール・注意事項

*ソースを読まないと分からない仕様を箇条書きで書き出す。*

- ***固定値*** … コードに直接書かれている定数の意味。
- ***設定値*** … 設定ファイル／プロパティから実行時に読む値。**キー名と既定値まで**書く。
- ***制約*** … 実装上の制限（文字列検索によるパースの限界など）。
- ***既知不具合*** … 未実装スタブなど。「直すかどうか」ではなく「現状こうなっている」という
  事実として書く（修正の可否はPM判断）。
- ***排他制御*** … ロック・トランザクション境界に関わる事項。

### 2.4 対象項目

*サンプル`KAZS012`の「2) 対象項目について」に対応する。本章で唯一の表。*

- ***No.*** … 対象テーブル内での項目の通し番号。テーブル定義側のNo.をそのまま引き継ぐ
  （サンプルは`No.7`から始まっている。1から振り直さない）。
- ***テーブルID／テーブル名*** … 例：`TAZSD001`／`注文データ`。複数テーブルある場合は
  テーブルごとに行をまとめる。
- ***項目名／項目ID*** … 例：`営業所コード`／`EIGYOSHO_CD`。
- ***対象*** … `○`＝対象とする／`×`＝対象としない／`△`＝条件付きで対象。
  `△`を使う場合は必ず「備考」にその条件を書く（サンプルの`△`も
  「履歴対象とする。ただし、変更のあった納期の納期名を1行登録し、変更内容は登録しない。」と条件付き）。
- ***課題No.／備考*** … その行の根拠・経緯にあたるBacklog課題キーと補足。
  サンプルでは項目単位で`AZS-2628`等が付いており、項目ごとに経緯が異なる。ここは特に埋める。
- *項目単位の対象・非対象という概念が無い機能では「該当なし」＋理由。*

### 2.5 参照ドキュメント

*詳細が他ドキュメントにある場合、そのドキュメント名を書く。サンプル`KAZS001`のように
`【処理概要】`が`「Ⅴ-7-01.採番一覧」参照`の1行だけ、というケースを受けるための小節。
自ページで完結する場合は「該当なし」。丸投げにせず、参照先で何が分かるのかも一言添える。*

## 3. 対象画面・ボタン・項目

| 機能ID | ファイル |
| -------------- | ---------- |
| （記入）       |            |

*各項目の意味と記入内容：*

- ***機能ID*** … 呼び出し元の機能ID（OPFパッケージコード。例：`S001A`）。画面コード（`C11`等）ではなく
  パッケージコードで統一する（4-1のマトリクス列見出しと揃えるため。1機能が複数画面を持つ場合も
  呼び出し元は1行にまとめる）。
- ***ファイル*** … 呼び出しが存在するファイル名（例：`lyr07_C11Entity.java`）。
- ***行番号は書かない*** … 上記「共通の記入ルール」のとおり。件数（「21機能、172呼び出し箇所」等）は
  規模感が伝わるため表の前後の文章に書いてよい。
- *特定のボタン押下ではなく「検索実行時」「`PreparedStatement`実行直前」のように呼び出し契機が
  決まっている場合は、表の前にその契機を明記する。*

## 4. 更新仕様（対象テーブル）

*この共通機能自身がDBに書き込むかどうかを書く。*

- *書き込む場合は、対象テーブルと更新するカラム（およびその値の作られ方）を記載する。*
- *書き込まない場合は**「該当なし」＋理由**を書く（例：SQL文字列を組み立てて返すのみで、
  実行は呼び出し元Entityの責務であるため）。単に空欄にしない。*
- *対象テーブルが呼び出し元次第で変わる（任意のテーブルに横断的に作用する）場合は、
  その旨と、横断的に付与される列だけを書く。*

*各項目の意味と記入内容：*

- ***共通機能ID／対象テーブル*** … 「4. 更新仕様」で特定したテーブルを記入する。DBを更新しない
  機能の場合は「該当なし（〜のため）」と理由まで書く。
- ***項目名*** … 対象テーブルのカラム名。
- ***キー*** … その操作の抽出キーになるカラムに印を付ける。
- ***UPDATE／INSERT／DELETE*** … 各操作でその項目に何を設定するか（値・式・`sysdate`等）を書く。
  操作対象外なら空欄。
- *DBを更新しない機能では2つの表とも「該当なし」で構わないが、**そう判断した根拠**
  （どの範囲をソース調査して書き込みが無いと確認したか）を表の後に1文添えること。*
